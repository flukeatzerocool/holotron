[HIGH] H1 — Borrowed-door (lesser ending) is STILL unreachable in play
  Location: index.html:636 (every descending-stair things=['exit-key']),
            1168 (pickup auto-grants G.key), 1198-1203/1214-1216 (descent
            requires a descending-stair), 1234-1238 (attemptExit)
  The prior fix claimed the borrowed ending was RESOLVED and "attemptExit()
  wins with wonType==='borrowed'." That is only true if G.key is false.
  In real play G.key can never be false once the player has descended:
  every descending-stair room carries exit-key (636), pickup() auto-grants
  it on room entry (1168), and descending (the only route to the ground
  floor) requires standing in a descending-stair (1216). npcItemSweep never
  removes exit-key (1261). So by the time the player stands on the
  ground-floor stair, G.key is true and attemptExit() takes the key branch
  first (1236), shadowing the borrowed branch (1237).
  Evidence (harness key trace): keyVal == "KEY HELD" on floor 1 BEFORE the
  first descent, and at every depth thereafter; a full descent + Escape
  produced winTitle "You escaped on your own light." (full), never borrowed.
  GDD §2.9 lists the borrowed door as a first-class lesser ending (400 pts,
  "you slipped out in another's wake"), and §8 screen inventory names a
  borrowed victory banner. The feature is dead in practice.
  Fix: gate the key branch — e.g. offer borrowed escape when the door is
  open even if the key is held (player choice), or make exit-key optional
  (place it on only one route / do not auto-collect), or make the borrowed
  door a mutually-exclusive route. Also ensure attemptExit prioritises the
  borrowed offer when borrowedOpen.

[MEDIUM] M1 — Near-Miss Bonus is now once-per-run, not "+50 each"
  Location: index.html:1180-1183 (G.nearMissFlag set globally at 1182)
  The prior LOW fix over-corrected. G.nearMissFlag is a single global boolean
  set on the first award and never cleared, so at most ONE +50 near-miss can
  be scored in an entire run. GDD §2.9/§4.4 define it as "+50 each" for
  grazing a creature or escaping a room at wax ≤ 3, a first-class always-
  available reward. The guard should be keyed per room (or the flag reset),
  not global.
  Fix: key on G.depth+':'+slug (e.g. a Set), or reset nearMissFlag on room
  exit; keep the same-room re-entry guard only.

[MEDIUM] M2 — npcItemSweep can still permanently remove a required item
  Location: index.html:1254-1267 (sweep), 1320-1323 (recovery)
  The prior fix only guarantees a room keeps its LAST item and protects
  exit-key. A 2-item candle-nook (wax-cake + matches) can still have one
  required item taken; recovery happens only inside openBorrowedDoor(), i.e.
  only if that NPC reaches the ground-floor door. If the NPC never escapes,
  the stolen wax-cake/matches are gone from the floor, undermining the
  per-floor required-things guarantee (GDD §2.2/§5). The finding's own
  recommendation ("skip protected/required items") was not implemented.
  Fix: make npcItemSweep refuse items in TEMPLATE.required_things, or drop
  carried items whenever the NPC is relocated/removed, not only on escape.

[MEDIUM] M3 — No screenshake and no hit-stop; particles minimal
  Location: index.html:1755-1763 (10 dust motes only); no shake/hit-stop
  Carried over from the prior run (explicitly deferred to juice_agent). In
  this reviewed build there is still no camera shake and no hit-stop/freeze
  on snuff/endure/near-miss. Reviewed brief lists these as game-feel items
  to verify. Remains a gap until Phase 5.5.
