[HIGH] Q key descends from ANY room — sequence-break exploit
  Location: index.html:1870 (also 1192-1198)
  The keydown handler maps 'q'/'Q' directly to descend(), and descend()
  (1192) has no guard requiring the player be standing in a
  `descending-stair` room. Contrast tryMove('down') at 1176-1182, which
  correctly checks `room.archetype==='descending-stair'`. Pressing Q on
  the Spire (or any floor) immediately drops a floor, bypassing the
  entire routing/exploration loop and the exit-room affordance.
  Fix: only descend when `G.floors[G.depth].rooms[G.pos].archetype===
  'descending-stair'` (guard inside descend() so every caller is safe).

[HIGH] Borrowed-door / lesser ending is unreachable (dead required feature)
  Location: index.html:738-746 (spawn), 1259-1265 (escape loop), 1277-1283
  NPC floors are fixed at spawn from the roster map: vlask 2, marta 2,
  petr 2, ilona 3, nadja 3 — clamped to [2,6] (741). No NPC is ever on
  MAX_DEPTH (6), n.floor is never reassigned anywhere (only assignment is
  line 745), and simNpcs only moves NPCs within the active floor. The
  escape loop `if(n.floor!==MAX_DEPTH||!n.room) return;` therefore never
  fires, so openBorrowedDoor() is never called and the borrowed-door win
  path (attemptExit 1210) plus its `G.borrowedOpen` decay branch (1267-1271)
  are all unreachable. GDD §2.9 makes this a first-class ending.
  Fix: let NPCs descend (advance n.floor when they leave a descending-stair),
  or spawn/route at least one NPC to MAX_DEPTH during sim.

[HIGH] Creature effect double-charge (wax-drain and turn-cost)
  Location: index.html:1332, 1334, 1342
  `spill` already encodes wax-drain=3 and defaults turn-cost to 1 (1332),
  then the code separately does `if(eff==='turn-cost'){ burnWax(2); }`
  (1334) and `if(eff==='wax-drain'){ burnWax(2); }` (1342). Shades cost
  3+2=5 wax; spiders cost 1+2=3 wax on Run. Effects are applied twice,
  so the GDD/roster effect numbers are silently inflated.
  Fix: apply each effect once — either through spill or the explicit
  branch, not both.

[HIGH] Dread never sets survivors' starting disposition (mechanic missing)
  Location: index.html:787-794 (seedDispoForFloor — never called)
  GDD §2.6/§2.7 require new NPCs on floor 2+ to start one step warier at
  Watched+ and all-Hostile at Hunted-full. seedDispoForFloor() implements
  exactly this but is dead code — grep shows no call site. NPCs enter with
  template base numeric regardless of Dread. The Dread→wariness pillar is
  unimplemented.
  Fix: call seedDispoForFloor(n.numeric) when an NPC first becomes
  co-located/active on the player's floor.

[HIGH] Encounter resolution does not advance the turn/simulation
  Location: index.html:1330-1368 (resolveCreature/resolvePuzzle)
  GDD §2.1 defines a turn as "move one tile, wait, take/use an item,
  resolve an encounter action, or perform a social action." Social actions
  call takeTurn('social') (1404), but creature/puzzle resolution only
  burnWax() and close the modal. Consequences: (a) NPCs do not simulate,
  (b) during the guttering dark, grace is NOT decremented while the player
  resolves uncleaned encounters, freezing Orlok's approach, and (c) the
  turn counter/score cadence desyncs. Also, enterRoom() opens the encounter
  modal and then tryMove still runs takeTurn('move') on the same step, so
  the move turn is paid before the encounter is even answered.
  Fix: have resolveCreature/resolvePuzzle call takeTurn (or an equivalent
  turn-advance that decrements grace and simNpcs) after applying costs.

[HIGH] Encounter modal has no keyboard confirmation (Space) 
  Location: index.html:1857-1870 (keydown)
  GDD §3.3: "In an encounter, Space confirms the highlighted option."
  The keydown handler returns early whenever isModalOpen() and only treats
  digits 1-6 for the social modal (1859-1862). Space/WASD/arrows do
  nothing while the encounter modal is open, so keyboard-only users cannot
  resolve Run/Endure or puzzle choices and cannot dismiss with Space.
  Fix: handle Space/arrow+Enter for modal-encounter (and Esc to close modals).

[MEDIUM] NPCs never roam floor-to-floor; floors 4-6 have no social layer
  Location: index.html:1239-1272 (simNpcs), 738-746
  Direction §6.5 and GDD §2.2 require survivors to "roam and change floors
  like you." simNpcs only relocates an NPC within the active floor; n.floor
  is immutable. Because floor assignment is fixed (max 3), the player never
  meets a survivor on floors 4-6, contradicting the tower-wide roaming
  premise (and indirectly causing the borrowed-door dead-end above).
  Fix: move NPCs through `up`/`down` exits during simulation.

[MEDIUM] Escape with a modal open opens Pause underneath it

  encounter/social/journal modal open, Esc switches to the Pause screen
  while leaving `.modal.active` set, producing stacked overlays; Resume
  (1831) then returns to gameplay with the modal still open.
  Fix: if isModalOpen(), Esc closes the modal and returns.

[MEDIUM] Live `things` never reflects pickups (worldState desync)

[MEDIUM] Multiple descending-stairs are not linked symmetrically

  a different room than they left from.

  descent to the linked exit.

[MEDIUM] Tapping empty space on a descending-stair forces descent/escape
