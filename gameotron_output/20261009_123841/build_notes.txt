============================================================
CONTROL HANDLERS
============================================================
Unified pointer abstraction: pointerDown/Move/Up(x,y).
- Touch:  cv.addEventListener('touchstart'|'touchmove'|'touchend'|'touchcancel'),
          first tracked touch (identifier); preventDefault on all; passive:false.
          touchend / touchcancel both route at last point.
- Mouse:  cv 'mousedown', window 'mousemove'/'mouseup', cv 'mouseleave'
          (release while pressed). Both schemes run simultaneously behind a
          single pointerActive guard (first pointer wins).
- UI:     document 'pointerdown' delegation for [data-action] buttons and
          [data-setting] toggles (pointer-agnostic: works touch + mouse);
          pause button has its own handler. Listeners attached once.
- Sizing: touch routing pads are >= 96 CSS px (design target >= 88 px);
          pause button 52 px.
- Keyboard: intentionally NOT used per GDD §3 ("no keyboard").
- Auto-pause on document visibilitychange per GDD §7.

Core loop implemented exactly: tap-and-hold the central button to charge
(T1 0–1s / T2 1–2s / T3 2–3s, capped by zone), release to roll a weighted
outcome token, drag the token to its zone:
  Resource -> VAULT (right), Upgrade -> SOCKET (top), Enemy -> CANNON (left),
  Junk -> flick off any screen edge (Zone 3+). Wrong pad = fizzle; empty
  drop = snap back and continue the lifetime clock. NO nested mini-games.

============================================================
AUDIO NODES (all procedural WebAudio)
============================================================
Graph: source(s) -> BiquadFilter(optional) -> GainNode envelope
       -> busGain(music | sfx) -> masterGain -> destination.
- One AudioContext created/resumed on first user gesture; every SFX/helper
  no-ops safely if the context is missing or suspended (never throws).
- Precomputed 2s white-noise buffer reused for all noise bursts.
- Helpers: Audio.tone({type,freq,dur,attack,gain,filter,filterType,pitchBend,
  detune,bus,time}) and Audio.noise({dur,filter,filterType,Q,gain,pitchBend,
  attack,bus,time}); nodes auto-stop and disconnect on 'onended'.
- Machine hum: continuous sine oscillator (55Hz) on the music bus, pitch/gain
  track the charge state (55 -> ~125 Hz while holding).
- Music: lookahead step scheduler (setInterval 25ms, ~120ms ahead, 16-step
  loop). Tempo = 104 + (zone-1)*8 BPM capped 160. Layer schedule by zone:
  kick (Z1+), snare/hat + calliope arp (Z2+), pad + ratchet ticks + minor
  color shift (Z3+), off-beat bass (Z4), sparkle accents (Z5). Scheduling
  guarded against runaway loops (max 32 steps per tick).
- SFX events: ui_click, ui_toggle, button_press, roll_release, token_spawn,
  resource_collect (combo-pitched semitone ladder), upgrade_install,
  enemy_defeat, wrong_route, near_miss, zone_transition (arpeggio per zone),
  combo_milestone, jackpot, stability_warning, game_over, victory,
  title_demo_roll, pause_in, resume_out.
- Independent music/sfx bus toggles with 100ms ramps; persisted to
  localStorage key teb_settings { music, sfx, reducedFlash }.

============================================================
INTENTIONALLY SIMPLIFIED (vs. full GDD)
============================================================
- One primary active token at a time; the "chained second token while the
  first is mid-drag" (Zone 2+) is not implemented. Zone-4 double-enemy waves
  and the Twin Roller module do spawn two tokens, so multi-token routing and
  hit-testing are supported.
- Per-zone background music does not gate on a completed bar boundary; tempo/
  layer changes apply immediately at the next scheduled step (click-free but
  not bar-quantised). Music bus fades in/out on pause/resume.
- Music-bus ducking for zone fanfare/jackpot and the <30 stability heartbeat
  motif are represented only by the SFX themselves (no side-chain ducking /
  recurring pulse loop).
- Title logo/gear animation is a CSS/DOM logo over the canvas idle scene with
  confetti rather than a bespoke illustrated machine logo.
- Score odometer rolls via eased count-up; other stat reveals are static.
