[HIGH] Spring on wax-cost traps burns wax instead of snuffing — contradicts their own
       descriptions and the §6.1.1 cost grammar
================================================================================
Location: index.html:1771-1775 (resolveTrap spring branch), index.html:455-456 (template
          effects), index.html:1727 & 1731 (trapDesc collapsing-floor / pressure-plate),
          index.html:129 (How-to-Play), world_template.json:175-176.
Explanation: §6.1.1 fixes the trap grammar as "Spring -> snuffs the candle + costs a match".
`pressure-plate` and `collapsing-floor` are declared with `"effect":"wax-cost"`, so
`resolveTrap('spring')` falls into the `else { burnWax(2); ... }` branch and does NOT snuff.
Confirmed by harness: springing pressure-plate at 20 wax -> 17 wax, `snuffed` false.
But `trapDesc('collapsing-floor')` says "...spring it — the tile gives way and snuffs the
flame", `trapDesc('pressure-plate')` says "...the plate trips a snuff-ward", and the
How-to-Play text says "spring it and the flame is snuffed". The player is told a snuff and
gets a wax bill — a direct gameplay/text contradiction and a deviation from §6.1.1
("Avoid -> wax; Spring -> snuff + match").
Fix approach: align data and code. Either (a) set both traps' `effect` to `"snuff"` (and
regenerate/parity the embedded template + world_template.json), or (b) if a wax-cost spring
is intended, rewrite the descriptions/How-to-Play to say "spring it — wax is spilled", and
reconcile §6.1.1. (a) matches the brief.

[HIGH] Three of the six declared traps are dead data — snap-trap, light-glyph and
       cursed-ward never spawn on any seed
================================================================================
Location: index.html:643 (nH), index.html:685 (trapPool), index.html:687-693 (trap
          assignment), world_template.json:177-180 / index.html:457-460 (roster).
Explanation: `trapPool(d)` returns `traps.filter(floor<=d)` **in roster order**
[pressure-plate, collapsing-floor, snap-trap, spider-web, light-glyph, cursed-ward], and the
per-floor assignment uses `pool[trapIdx % pool.length]` with `trapIdx` reset to 0 for every
floor. Per floor: one shadow-hall is consumed by the creature, and `nH` is capped at 3
(`Math.min(3, ...)`), so at most 2 trap slots exist and only pool indices 0 and 1 are ever
reached. Instrumented generator over 1,500 seeds x 6 floors: `snap-trap` 0, `light-glyph` 0,
`cursed-ward` 0 placements; only `pressure-plate` (5,273), `collapsing-floor` (1,542) and the
companion-forced `spider-web` (1,467) ever appear. The "traps escalate by density and region —
new types enter by tier" requirement (§6.1.2) and the §15 must-have "the remaining traps
(snap trap, spider web, light-glyph, pressure plate, cursed ward) by density" are unmet; three
authored trap types are unreachable code/data. `trapTitle`/`trapDesc` entries for them are
likewise never shown.
Fix approach: make trap selection reach the later roster entries — e.g. seed `trapIdx` from a
per-floor hash/offset, or index the pool by depth (`pool[(depth-2 + trapIdx) % pool.length]`),
or raise the trap budget, and/or introduce trap types by tier rather than as a fixed prefix.
Add a regression assertion that each declared trap can appear within the playable depth range.

[HIGH] D6 NPC-in-light is non-functional for roaming survivors
================================================================================
Location: index.html:2126-2132 (render/DrawScene NPC block).
Explanation: §6.3 requires survivors to be "visible on the map whenever they are inside your
visibility range ... you watch them move turn by turn". The new brightness/silhouette code is
still nested under `if(r.npc)`, where `r.npc` is a static field set once at floor generation
(index.html:718/735) for the room a survivor *started* in. `simNpcs()` (index.html:1616-1648)
reassigns `n.room` as survivors roam, but never sets `rooms[...].npc` on the destination room,
so a roamed survivor has no `r.npc` gate anywhere. Harness (test_seed, 10 turns at depth 3):
Petr ends in `d3-candle-nook-2` (r.npc = null) => not drawn. In practice survivors leave their
camps within a few turns, so NPCs are effectively invisible on the map, defeating the D6 goal
(and the pre-existing §6.3 requirement).
Fix approach: iterate survivor positions instead of room fields — loop `Object.keys(G.npcs)`
on the active floor, read the NPC's actual room (`fl.rooms[n.room]`), compute distance to the
player's room, and draw at that room's screen coords (full-brightness <= radius, alpha 0.4
silhouette <= radius+1). Do not gate on `r.npc`.

[MEDIUM] "Go around" disarms the trap: avoid marks the room cleared and removes the telegraph
================================================================================
Location: index.html:1786 (resolveTrap avoid path sets `G.cleared[...]`), index.html:2135-2136
          and :1506 (encounter/telegraph gate on `G.cleared`).
Explanation: §6.1.1 fixes the persistent state change as `armed -> sprung` (only a *sprung*
trap is a permanent edit). Avoiding is supposed to cost only tempo/wax — the trap stays armed.
But `resolveTrap` sets `G.cleared[depth:slug]=true` on *both* branches, so after "Go around"
the room never re-triggers (`enterRoom`, index.html:1506) and its telegraph disappears
(index.html:2135). The floor is silently edited even though the trap was never sprung.
Fix approach: only set `G.cleared` in the `spring` branch (or track a separate
`G.sprung[depth:slug]` for persistence and leave the trap retriggerable/telegraphed after an
avoid).

[MEDIUM] Traps have no audio voice (§12) and AUDIO_SPEC declares no trap scenario
================================================================================
Location: index.html:1711-1712 (trap modal, no `Audio.*` call), index.html:2477-2488
          (AUDIO_SPEC scenarios).
Explanation: §12 "Traps have a voice" requires a distinct cue per trap type (stone grind,
coiled click, chitinous rustle, mechanism thunk, low glyph tone), attenuated outside the
radius. `openEncounter` plays `Audio.creature(...)` for creatures but emits nothing for traps,
and AUDIO_SPEC lists only bed/tick/creature/wax/guttering/victory. The SFX-independent visual
telegraph is implemented (good), but the audio half of the trap identity is absent.
Fix approach: add a trap cue dispatcher (per trap id) invoked from the trap branch of
`openEncounter`, and add a trap scenario to AUDIO_SPEC so Phase 2b can verify it.

[LOW] Repeated lore trades can duplicate hints; "fast stair" picks an arbitrary stair
================================================================================
Location: index.html:1882 (`G.loreHints.push(hint)`), index.html:1461 (`stairs[0]`).
Explanation: `hintForFloor` always computes the same floor hint, and each NPC trade pushes a
new copy; the journal then lists the same hint repeatedly. With multiple descending stairs,
`stairs[0]` is whichever key comes first in object order — not necessarily the "fast" stair.
Cosmetic/UX only.
Fix approach: de-duplicate `G.loreHints` on push; label the stair name generically
("a stair") or pick the stair nearest the entry/depth and say so.

Explanation: If `host` has no free neighbouring tile, `attach(host,'shadow-hall')` returns null

================================================================================
[LOW] keyRoom fallback can select a trap-role room (placement invariant edge)
================================================================================
Location: index.html:664-671.
Explanation: If a floor (pathologically) generates neither a candle-nook nor any scribe-alcove,
`keyRoom` falls through to `Object.keys(rooms).filter(s !== entry && archetype !==
'descending-stair')[0]`, which could be a `shadow-hall` (role `trap`). The floor-key and
lore-fragment would then be pushed into a creature/trap room, violating the §6.1.1 placement
invariant. Not observed (nP=2 and nT>=1 in all swept seeds), but the fallback does not exclude
`shadow-hall`.
Fix approach: exclude `archetype === 'shadow-hall'` (and any room with an
`encounter`) from the fallback keyRoom filter.
