[HIGH] window.AUDIO_SPEC is never defined although the game is a Web Audio game.
Location: index.html:2096 (missing definition; window.audioTest defined here only)
Explanation: §14 requires Web Audio games to expose BOTH window.audioTest(...) and
  window.AUDIO_SPEC (scenario list + thresholds; or {applicable:false}). audioTest is
  defined, but AUDIO_SPEC is absent. The puppeteer Phase 2b audio check will therefore
  report "unverified" (fail-closed), and the contract hook is incomplete.
Fix approach: After the Audio IIFE, add
  window.AUDIO_SPEC = { applicable:true,
    scenarios:['tick','creature','wax','guttering','victory'],
    thresholds:{ rms:0.001, bandRms:0.0005 },
    overrides:[{scenario:'tick', rms:0.0005, reason:'short 40ms blip'} ] };
  (values matched to Audio.offline scenario output), or declare {applicable:false} if
  you truly have no AudioContext.

[HIGH] Hazard must-haves are unmet: only 3 of 5 hazards exist, none costs a match on
  "spring", and hazards are modelled as kind:"puzzle" rooms rather than hazard archetypes.
Location: index.html:447-449 (roster); index.html:1557-1565 (resolvePuzzle)
Explanation: §15/§6.4.4 require five hazards (collapsing floor, light-glyph, pressure
  plate, cursed ward, crumbling stair) with the grammar "avoid costs wax; spring snuffs
  the candle + costs a match". The roster ships only collapsing-floor(3), light-trap(4),
  dark-leap(5) — all kind:"puzzle" — and "Press on" (spring) only sets G.snuffed without
  consuming a match, so the specified cost grammar is not implemented. This is a named
  must-have gap.
Fix approach: Add the missing roster entries (pressure-plate, cursed-ward, crumbling-stair)
  and, on a spring that snuffs, consume a match (or require one) via G.matches-- with the
  same zero-match -> enterGuttering() branch used by resolveCreature. Prefer authoring them
  as hazard-role encounters distinct from the puzzle flavour.

[HIGH] The Spire (floor 1) generates two creature rooms plus puzzle rooms, violating the
  beginner tutorial constraint (at most one teaching creature; no hazards/social/puzzles).
Location: index.html:620-625 (nP>=1, nH=(depth===1)?2)
Explanation: §6.4.1/§9/§15 state the Spire is a gentle wax-and-exploration tutorial carrying
  at most a single teaching creature (bats), with no social, Dread or hazards. The generator
  forces nH=2 shadow-hall (bats) encounters AND nP>=1 scribe-alcove puzzle encounters on
  depth 1, so a new player meets two creature encounters and a puzzle before learning the
  loop. This threatens the "first success well inside 30s" jam requirement.
Fix approach: On depth===1 set nH=1 and nP=0 (keep the guaranteed wax refill adjacent to the
  entry). Move puzzles/hazards to depth>=2 (already the social/hazard intent).

[HIGH] A puzzle snuff with zero matches does NOT enter the guttering-dark grace.
Location: index.html:1557-1565 (resolvePuzzle risk/snuff branch; cf. 1536-1537)
Explanation: §8/§6.4.1 require that a snuff recoverable only while holding a match; with zero
  matches the snuff must drop the player into the guttering-dark grace (the tower's one
  terminal path). resolveCreature() implements this (line 1537), but resolvePuzzle() only
  sets G.snuffed and then checks G.wax<=0 — it never checks G.matches<=0. Result: a
  light-trap/cursed-ward snuff with no matches leaves the player permanently snuffed
  (radius 1) with no grace and no death, contradicting the spec and the snuff/guttering
  distinction.
Fix approach: Mirror the creature path: after a snuff in resolvePuzzle, add
  if(G.wax<=0 || (G.snuffed && G.matches<=0)) enterGuttering();

[HIGH] Lore is not tradeable — the wave-2 "social key" must-have is not implemented.
Location: index.html:1628-1653 (applySocial); index.html:432-438 (social_actions)
Explanation: §15/§5.1 require lore, in wave 2, to buy disposition, information, or safe
  passage — never wax or matches. applySocial() never reads G.lore/G.loreFragments; the
  bargain/trade actions only mutate disposition/wax. Offering lore has no effect, and no
  information/passage reward exists. Lore is therefore flavour-only (wave 1), not the social
  key.
Fix approach: In applySocial for bargain/trade, if the player holds lore and the target's
  disposition cap permits, grant a disposition bump or a hint (reduced exploration = saved
  wax) or a one-use safe-passage flag; never award wax/matches. Bounded by the per-NPC cap.

[MEDIUM] Wave-3 NPC item use is effectively inert — the skip-list blocks every item type.
Location: index.html:1397-1414 (npcItemSweep), 1402-1406
Explanation: §15 requires NPCs to carry/take/use items (independently flag-gated). But
  npcItemSweep skips any item in REQ_THINGS ['wax-cake','matches','lore-fragment','floor-key']
  plus 'floor-key' — i.e. all item types that exist. The sub-feature can never fire, so the
  "NPCs take/use items" flag does nothing.
Fix approach: Introduce at least one non-required consumable (e.g. an "oil-vial" or loose
  "spare-wax" thing) that is safe to take, and allow NPCs to consume it; or narrow the
  skip-list to only 'floor-key' + explicitly required key fragrances.

[MEDIUM] Wave-3 "NPCs trip traps" is inert — n.tripped is set but never read.
Location: index.html:1437-1440 (setting), 1439
Explanation: The flag npcTrapTrip sets n.tripped when an NPC co-locates with a puzzle, but
  nothing consumes n.tripped: no hazard state change, no route change, no persistence edit.
  It is a dead simulation branch, so the flagged sub-feature is non-functional.
Fix approach: Tie n.tripped to the hazard state (mark the room's encounter cleared/sprung and
  persist that edit on the floor), or remove the flag rather than shipping an inert toggle.

[MEDIUM] worldState() strips vertical (up/down) exits, hiding the contract's staircase graph.
Location: index.html:711-720 (snapshotRooms filter), index.html:691-694 (exit creation)
Explanation: §14 defines vertical movement as down/up exits and the Phase-2 checker validates
  the generated layout. snapshotRooms() drops any exit whose target slug is not in the
  current floor's rooms, so the descending-stair room's `down` (and the entry's `up`) never
  appear in worldState(). A checker looking for the descent/exit edge sees a leaf room and
  cannot confirm tower connectivity.
Fix approach: Emit vertical exits as explicit metadata (e.g. room.exitDown = 'floor d+1',
  room.exitUp = 'floor d-1') in snapshotRooms rather than silently filtering them, or keep
  the slug and let the checker treat cross-floor slugs as valid vertical links.

[MEDIUM] G.key (HUD) desyncs from per-floor G.floorKey — gate passes while HUD says "no key".
Location: index.html:1080 (HUD), 1320-1322 (gate check), 1345 (G.key=false on descend)
Explanation: The gate check uses per-floor G.floorKey[depth], but the HUD "Key HELD" uses the
  single global G.key, which descend() resets to false. After descending then re-ascending
  to a floor whose key you already found, G.floorKey[depth] is true (gate opens) yet the HUD
  reads "no key". Visual/state contradiction.
Fix approach: Derive the HUD key indicator from G.floorKey[G.depth] (or set G.key from
  G.floorKey[G.depth] on entry/ascend), so the display matches the gate logic.

[MEDIUM] A snuff has no distinct visual "hard cut" — it is visually identical to guttering.
Location: index.html:788-794 (effRadius), 2034-2037 (guttering red pulse)
Explanation: §8/§11 require a snuff to read as a hard instant blackout, visibly distinct from
  the slow guttering dark. In code both snuffed and guttering return effRadius()==1 and only
  the guttering branch draws a red pulse, so a snuff shows no distinct frame cue (the audio
  cut in Audio.snuff exists, but the visual requirement is not met).
Fix approach: On the transition into G.snuffed, flash the whole frame to pure black for a
  frame or two (a distinct cut), and/or tint the mask differently from the guttering red.

[MEDIUM] Every noise SFX allocates a fresh 1.5s audio buffer, including the per-turn tick.
Location: index.html:832-838 (noiseBuf), 865-877 (noiseAt), 966 (tick)
Explanation: noiseAt() calls noiseBuf(), which allocates a 1.5*sampleRate Float32 buffer on
  every invocation. Audio.tick() is called for every turn, so ~66k floats are allocated and
  discarded per turn (and per creature cue). This is avoidable GC churn / memory pressure on
  mobile for 25ms blips.
Fix approach: Create one shared noise buffer lazily (cache per AudioContext) and reuse it for
  all bandpassed noise sources; only regenerate if the context changes.

[MEDIUM] Hazards have no intrinsic pre-commit telegraph — the encounter fires on room entry.
Location: index.html:1291-1315 (enterRoom -> openEncounter), 1886-1907 (archetype glyphs)
Explanation: §6.4.1/§15 require every hazard to be readable before committing, with an
  intrinsic cue inside the spill ring readable with SFX off. Here a hazard's choice modal
  opens only after the player has already moved into the room, and the only cue is the generic
  archetype glyph. There is no distinct hazard telegraph (crack/pulse/dust) that says "this
  room taxes light" before the move.
Fix approach: Draw a hazard-specific telegraph in drawScene (e.g. hairline crack / glyph
  pulse) for rooms carrying a hazard-role encounter, visible when revealed and SFX-independent.

[LOW] Dead CSS rule #talkBtn is never applied (element id is btn-talk).

[LOW] Inconsistent wax-clamp default (||30 vs ||40) across the same resource.
Location: index.html:1219 (burnWax uses WAXCLK.max||30), 1272 (pickup uses WAXCLK.max||40)
Explanation: Two different fallback maxima for the wax clock invite divergence if the template
  clock is ever missing. The template defines max:40, so ||30 under-counts on fallback.
Fix approach: Use a single derived WAX_MAX constant (from WAXCLK.max || WAXR.max || 40).

[LOW] setTimeout-scheduled audio tones are not cancelled on run reset/end.
Location: index.html:967, 980, 984, 999, 1001
Explanation: waxFound/victory/zone/creature(bats)/social schedule follow-up tones via
  setTimeout. If the player ends or resets the run within the delay, the stale tone still
  fires on the persistent AudioContext. Harmless audibly, but unguarded and flagged by the
  review brief.
Fix approach: Store timer ids and clear them in Audio.resetMix()/newRun(), or replace with
  scheduled OscillatorNodes (toneAt already accepts an `at` offset).

[LOW] seed_default in the template is ignored; default runs always use test_seed.
Location: index.html:537-540, template index.html:274-275
Explanation: §4 says the default seed is random and overridable. The resolution order uses
  window.SEED -> ?seed= -> TEMPLATE.test_seed -> Math.random, so without an override every
  default run is the fixed test seed 20261010. seed_default:null is never consulted.
Fix approach: If a random default is intended, move test_seed behind an explicit
  "seeded mode" trigger (e.g. ?test=1) or read TEMPLATE.seed_default when present.

[LOW] Keyboard controls are implemented although "full controls" was not requested.
Location: index.html:2193-2221 (keydown)
Explanation: §13 allows optional keyboard only when explicitly requested. Keyboard is present
  (WASD/arrows, Space, Esc, 1-6, Q). It does not conflict and is a harmless superset, but it
  is out of the requested scope; note it and keep mouse/touch as the primary path.
Fix approach: No change required; flag as intentional extra. Ensure Esc (pause/close modal)
  remains safe when focus is in an input (none exist) and that Space does not scroll
  (body overflow is hidden).

[LOW] window.social() contract hook diverges from the UI social flow.
Location: index.html:2068-2072 vs 1612-1619
Explanation: The UI handler runs applySocial -> takeTurn -> checkCoLocation -> renderHUD;
  window.social() calls only applySocial, so it neither advances the turn nor runs
  co-location. It remains a usable mutation hook, but a checker driving social through it
  under-observes the real flow.
Fix approach: Either document the hook as a pure mutation accessor or have it mirror
  takeTurn('social')/checkCoLocation() so tests exercise the same path.

[LOW] Magic seed/spacing numbers inline (999/555/777) lack named constants.
Location: index.html:741, 751, 760
Explanation: Derivation seeds and mixing constants are hard-coded, harming readability and
  making future tuning error-prone.
Fix approach: Extract named constants (e.g. SEED_DREAD_MIX=999, SEED_NPC_MIX=777).
