[MEDIUM] (CARRIED — deliberately deferred in cycle 2, not a regression) Hazards are still placed
  in a `role:"puzzle"` room; the `role:"hazard"` archetype holds only creatures, so §14's
  invariant "a hazard's room carries archetype `role:"hazard"`" is not met, and the hazard sits
  in the key room (a leaf/cut-edge), contradicting §6.4.1's "never on a cut-edge".
Location: index.html:447-452 (roster `kind:"hazard"`), index.html:671 & 674-678
          (`puzzleListAt` / scribe-alcove assignment), index.html:653-658 (floors 2-6 key room
          = first `scribe-alcove`), archetypes index.html:298-318 (`shadow-hall.role:"hazard"`,
          `scribe-alcove.role:"puzzle"`).
Explanation: Cycle 2 fixed the roster half (the five hazards are now `kind:"hazard"`, lines
  447-451) but explicitly left the room half UNFIXED. As shipped: every hazard is assigned to a
  `scribe-alcove` (archetype role:"puzzle", lines 677-678), while the only `role:"hazard"`
  archetype (`shadow-hall`) receives the creatures (`creatureFor`, line 676). §14 requires the
  hazard's room to carry role:"hazard". Separately, because floors 2-6 place the floor-key in the
  same first `scribe-alcove` (lines 653-658), the hazard's room is a leaf whose edge is a
  cut-edge on the critical path to the key, whereas §6.4.1 states a hazard is "never on a
  cut-edge ... every hazard has a bypass". Mechanically harmless today (the player loots the key
  on entry, and the encounter modal only taxes wax/snuff), and the Phase-2 checker passes, so
  this is a data-model / spec-conformance deviation rather than a playability defect.
Fix approach: (unchanged from cycle 2) Author a dedicated hazard archetype with `role:"hazard"`
  plus connectivity `corridor -> hazard` / `hazard -> corridor*`, place the five `kind:"hazard"`
  entries there, and keep `scribe-alcove` for the routing puzzles. Because this is an
  archetype/connectivity restructure, it was judged beyond the surgical-fix directive and
  deferred; it is re-filed so the residual non-conformance is explicit in the final cycle.

[LOW] A match used to end the guttering dark at wax = 0 does not stay re-lit: the next turn
  immediately re-enters guttering, refreshing the grace counter, so each held match buys a
  further full grace window and the terminal state can be postponed while matches last.
Location: index.html:1631 (`tryRelight`: `G.guttering=false`, no wax added) and
          index.html:1271-1275 (`takeTurn`: `burnWax` -> `if(G.wax<=0) enterGuttering()`, which
          re-sets `G.grace` at 1257).
Explanation: This is a direct consequence of the cycle-2 decision to align with gdd.md §2.8
  ("a match relights and ends the guttering dark", gdd.md:156/489). It adds no wax (no exploit
  of the wax economy — verified), but because wax is still 0 the candle re-gutters on the next
  takeTurn and `enterGuttering()` re-arms `grace = graceForTier()`. The devilled detail is that
  guttering is described as the terminal path (§8), yet a finite stock of matches can reset it.
Fix approach: Optional polish only. If a match should end guttering outright, record a
  `G.relitNoFuel` latch that suppresses automatic re-gutter until wax > 0 (or the next wax
  pick-up); otherwise leave as-is and consider a one-line note in gdd.md that a fuel-less
  re-light is provisional. Not a blocker.

[LOW] Vertical `up` exits and `ascend()` have no player-facing affordance: no button, no key
  binding, and `tapAt` maps only grid-adjacent same-floor rooms, so a player cannot ascend.
Location: index.html:1362 (`tryMove('up')` reachable only via the `window.move` hook),
          index.html:1387-1398 (`ascend()`), index.html:1909-1917 (only cardinal exit notches
          are drawn), UI bindings index.html:2286-2315 (no Up/Ascend control).
Explanation: gdd.md §2.2/§10.3 lists "down/up exits" and in-place backtracking (TORRE §6.5),
  and the engine generates `up` exits (line 709) and exposes `exitUp` in `worldState`. But the
  controls (§3) map only WASD/arrows to cardinals and no Ascend button exists, so backtracking is
  a model-level capability the player cannot exercise; the core descend-to-ground-floor loop is
  unaffected. Pre-existing; noted for spec/implementation completeness, not a new regression.
Fix approach: If backtracking is intended in play, add an "Ascend" affordance at rooms whose
  `exits.up` is set (mirror the Descend button at index.html:2277-2279); otherwise amend the
  GDD to state the descent is one-way.

[LOW] gdd.md internal contradiction on match value (spec-only; code follows the clarifying note).
Location: gdd.md:227 ("re-light a snuffed candle (restores candle to 8 wax)") vs gdd.md:489
          ("clears the snuff, adds no wax"); implementation index.html:1631 adds no wax.
Explanation: The two GDD statements disagree. The code implements §489 / §2.8 (no wax). No code
  change is warranted; the spec should be made self-consistent to avoid re-opening this.
Fix approach: Correct gdd.md:227 to read "re-light a snuffed candle (adds no wax)".

[LOW] Keyboard controls present although "full controls" was not requested (carried WONTFIX).
Location: index.html:2286-2315.
Explanation: WASD/arrows/Space/Esc/1-6/Q are implemented; §13 makes keyboard optional. Harmless
  superset, does not affect touch/mouse. Carried from cycle 1/2; no change required.
